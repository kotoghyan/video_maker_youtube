# Подключение YouTube

Реализованы команды без загрузки медиа:

```powershell
.\.venv\Scripts\python.exe -B -m vinyl_codex youtube-check
.\.venv\Scripts\python.exe -B -m vinyl_codex youtube-connect
.\.venv\Scripts\python.exe -B -m vinyl_codex youtube-status
```

Вход открывается в системном браузере. Владелец самостоятельно выбирает Google-аккаунт и существующий канал, затем разрешает доступ. Ожидание по умолчанию — 600 секунд; `--timeout 1800` увеличивает его до 30 минут. После истечения времени повторить команду. Для смены аккаунта: `youtube-connect --reconnect`. Прежний токен заменяется только после получения и проверки нового ответа OAuth.

Разрешения: `youtube.readonly` для проверки канала; `youtube.upload` для будущей отдельно утверждённой загрузки. Код этого этапа содержит только OAuth-обмен, обновление токена и GET channels.list. Загрузок, удаления, изменения видео и работы с комментариями нет. Подключение не подтверждает канал для публикации и не утверждает материалы или права.

Desktop OAuth JSON читается из `%LOCALAPPDATA%\Vinyl_Codex\credentials`: требуется ровно один JSON с секцией `installed` и официальными адресами Google. Исходный пользовательский файл не изменяется и не копируется в проект. Новые access/refresh токены хранятся исключительно в `youtube-token.dpapi`, зашифрованном Windows DPAPI для текущего пользователя Windows. Запись атомарная; временный файл содержит только шифротекст. Параллельные процессы исключены файловой блокировкой Windows. Пути OneDrive, проекта, архива и рабочих публикаций запрещены для хранилища, ссылки и junction запрещены.

OAuth использует случайные state, PKCE S256 и временный listener только на 127.0.0.1 со случайным портом. URL callback, коды, токены, client_id/client_secret и ответы ошибок Google не выводятся в журналы. Передача секретов допускается только официальному OAuth endpoint; HTTP-перенаправления запрещены. Никакие музейные медиа не передаются.

При успешной авторизации программа сохраняет токены и запрашивает название/ID канала. Если API временно недоступен, токен остаётся защищённым; повторять `youtube-status`, не проходить согласие заново. Повторная авторизация может понадобиться при отзыве/истечении refresh token. Отозвать доступ можно в настройках сторонних подключений своего Google-аккаунта; команда отзыва здесь ещё не реализована.

## Реальная проверка 10.10.2026

- Desktop JSON найден и валиден; содержимое и секреты не выводились.
- DPAPI encrypt/decrypt на этом ПК: успешно.
- `youtube-check`: ready_for_oauth; token_present=false; uploads=0 на момент проверки.
- 73 теста прошли, включая настоящий loopback callback с синтетическим кодом, отказ/подмену state, частичное согласие, Windows-блокировку, зашифрованную атомарную запись и обновление токена с mock Google API.
- Реальный Google OAuth и channels.list проверяются только после личного входа владельца. Результат тестов не означает, что канал уже подключён.

Источники: [Google Desktop OAuth](https://developers.google.com/identity/protocols/oauth2/native-app), [YouTube channels.list](https://developers.google.com/youtube/v3/docs/channels/list), [Windows DPAPI](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).

## Диагностика после двух успешных OAuth-входов

Проверены оба реальных GET: `channels?part=snippet&mine=true&maxResults=50` и `channels?part=id&mine=true`. Ответы успешно разобраны: `kind=youtube#channelListResponse`, `pageInfo.totalResults=0`, поле `items` отсутствует, поля `error` нет. Это пустой результат API, а не потеря найденных каналов в парсере. Токен действующий, OAuth-клиент соответствует исходному JSON, выданы оба запрошенных scopes: `youtube.readonly`, `youtube.upload`.

Ранее сообщение программы необоснованно предлагало выбрать другой аккаунт. Теперь пустой ответ получает отдельную диагностику без утверждения причины. Для следующего входа добавлен явный выбор аккаунта (`prompt=select_account consent`); новый реальный вход в ходе этой диагностики не запускался. Без дополнительных identity-scopes/email нельзя определить адрес Google-аккаунта из сохранённого токена; браузерный выбранный канал также не устанавливается этими scopes.

Причина не установлена. Проверяемые гипотезы: OAuth выдан для личной идентичности вместо канала Brand Account; либо доступ к каналу предоставлен только приглашением через Studio, которое не поддерживает YouTube APIs. Google описывает обе особенности: [Brand Accounts и сторонние программы](https://support.google.com/youtube/answer/3046478?hl=en), [ограничения приглашённых пользователей](https://support.google.com/youtube/answer/9481328?hl=en). Нужно уточнить тип канала и роль пользователя, затем выбрать обоснованное действие. Открытый канал в YouTube не доказательство неверного аккаунта и не подтверждение API-доступа.
