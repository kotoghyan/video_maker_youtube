# Vinyl Codex — контрольная точка 1

Актуальные незавершённые поручения пользователя: [TODO.md](TODO.md). Публикация 353 остановлена по просьбе пользователя: YouTube принял 10/13 видео, 9 публичных произведений подтверждены, альбом требует проверки; три оставшихся заблокированы лимитом канала. Утверждения сохранены, автоматического продолжения нет. Описания контрольной точки 1 ниже относятся к первоначальному этапу; OAuth и публикационный CLI реализованы в `docs/youtube-oauth.md` и `docs/youtube-publication.md`.

Для выбранных альбома и отдельных произведений добавлена локальная команда:
`python -B -m vinyl_codex prepare-record --recipe <WORK_ROOT/ID/selection.json> --ffmpeg <ffmpeg.exe>`.
Рецепт содержит явный Museum ID, путь, имя JSON, состав `both`, версию и проверенные
в чате роли фотографий. Для 353 получен официальный стандарт 10.10.2026;
METADATA/metadata.json читается явным именем, без изменения архивного файла и схемы.
Команда сохраняет побитовые копии TRACKS/IMAGES/METADATA, полные видео альбома
и отдельных цельных произведений, предложения Reels/Stories и подписи hy/en.
Для полного альбома PCM отсчёты TRACKS соединяются в музейном порядке без
добавленных пауз; AAC кодируется один раз, отдельные MP4 по звуку не склеиваются.
Проверяются PCM хеш сборки, длительность, начало звука, число аудиоотсчётов,
декодирование MP4, корреляция окон начала/середины/конца и неизменность архива.
Готовые версии не перезаписываются. `--resume` разрешён для прерванной версии
при неизменных рецепте и исходниках; непроверенные MP4 сохраняются отдельно.
Команда не вызывает сеть и API; согласование фрагментов, текстов и прав отдельно.
Текущая версия поддерживает одну пластинку, уникальные целые произведения без
`movement`, фотографии переднего/заднего конверта и сторон D01_A/D01_B.
После успешной подготовки: `python -B -m vinyl_codex build-review --recipe <selection.json>
--ffmpeg <ffmpeg.exe>`. Команда создаёт REVIEW.md со ссылками на каждую версию,
сопоставления постов/каруселей и миниатюру из оригинальной фотографии;
публикационные тексты фиксируются контрольными суммами до первого согласования.
Рендерер использует неподвижную проверенную лицевую обложку, не добавляет текст
или логотип. Фото других сторон входят в соответствующие карусели.

Управление через чат Codex и CLI; внешних зависимостей и публикационных API нет.
Python 3.12+. Конфигурация содержит только ARCHIVE_ROOT и WORK_ROOT.

Команды из корня проекта:

```powershell
.venv\Scripts\python.exe -B -m vinyl_codex doctor
.venv\Scripts\python.exe -B -m vinyl_codex doctor --check-write
.venv\Scripts\python.exe -B -m unittest discover -s tests -v
```

После разрешения на следующий этап и получения Museum ID:

```powershell
.venv\Scripts\python.exe -B -m vinyl_codex dry-run --museum-id <ID>
```

dry-run выдаёт JSON в stdout, ошибок — в stderr (код 2); ничего не сохраняет,
не вызывает сеть, не рендерит и не публикует. Отчёт не означает готовность публикации.
Поиск выполняется только в непосредственных подпапках архива по точному префиксу
`[ID] - `; другая структура требует отдельного решения, а не расширенного угадывания.
Ссылки и junction, пересечение рабочих путей с архивом, небезопасные ID запрещены.
Архив открывается исключительно на чтение; проверка записи допускается только в WORK_ROOT.
OneDrive-файлы с атрибутами отложенного чтения блокируются до скачивания владельцем.
Глобальная завершённость синхронизации OneDrive пока не определяется.

Стандарт прочитан 09.10.2026 через Google Drive:
[официальный документ](https://docs.google.com/document/d/16gsC0nYDbEBKahcXSvAxnK8yBGeGM-qvJP3Ixm6TUSc/edit?tab=t.0).
Локальная копия: docs/museum-standard.md. Документ содержит пример JSON, а не формальную
JSON Schema. Проверка воспроизводит набор полей примера, типы, ID, порядок треков,
имена и наличие локальных файлов TRACKS. Неизвестные поля и варианты типов
останавливают проверку для ручного решения; исходники не исправляются.
Атрибуции, группировка цельных произведений, смысловые связи VIDEO/IMAGES,
качество медиа, права, журнал и возобновление относятся к следующим этапам.

Для отдельной проверки заголовков медиа, независимо от структуры JSON:
`python -B -m vinyl_codex technical --museum-id <ID> --record <абсолютная папка>
--ffprobe <абсолютный путь ffprobe.exe>`.
Каталог должен находиться внутри ARCHIVE_ROOT; вложенная категория допускается
при явно заданном пути. Эта команда не подтверждает музейные метаданные.

09.10.2026 владелец разрешил чтение архивного варианта JSON пластинки 246.
Для него создан отдельный адаптер `legacy246.py`; он активируется только явно:
`python -B -m vinyl_codex dry-run --museum-id 246 --record <абсолютная папка>
--metadata-profile approved-246`.
Набор исходных полей фиксирован; Music не изменяется. Каждый объект Music
сохраняется целиком, включая Movement. Привязка к WAV проверяется по точному
префиксу ID/Disc/Side/Track и точному совпадению Composer + Work.
Неоднозначность, лишний файл или неизвестное поле останавливают проверку.
Адаптер не применяется к другим Museum ID и не изменяет официальный стандарт.

После выбора A01:
`python -B -m vinyl_codex prepare-a01 --record <папка 246> --ffmpeg <ffmpeg.exe>`. Команда предназначена только для первого выбранного A01.
Рабочие копии, полное видео, два фрагмента Reels и Story записываются в
WORK_ROOT/246/D01_A01/draft-v2. Версия v1 сохраняется как предыдущая. В готовый черновик повторно не записывает.
Прерванную подготовку можно продолжить с `--resume` после проверки исходных
хешей и разбора незавершённых выходных файлов. При наличии повреждённого MP4
он сначала сохраняется отдельно; его нельзя считать финальным результатом.
Блокировка prepare.lock исключает одновременную запись задачи.
state.json и журнал сохраняются атомарно. Состояние готовности допускается
после проверки длительности, полного декодирования экспортов и хешей исходников.
Публикационных действий в команде нет. Подписи и юридические разрешения
утверждаются отдельно. Видео без интро, аутро и отдельных титров, без зависимости от шрифта или логотипа.
Фотография и запись начинаются с нулевой секунды; конец совпадает с записью.
Полный звук без затухания, задержки, добавленной тишины и нормализации;
AAC в MP4 имеет потери, рабочая копия WAV совпадает с оригиналом.
Museum ID не добавляется в видео, обложки, Stories, заголовки, описания,
подписи и хештеги. Он остаётся только для внутреннего поиска, сопоставления,
рабочих путей, состояния и журнала. Архивные имена и JSON не менять.
Оригинальные фотографии и их надписи не ретушировать.
Код и документация хранятся в Vinyl_Codex; весь архив Karo, включая Armenian,
доступен только для чтения.

Структура:
- vinyl_codex/: config, safety, catalog, metadata, inventory, doctor, CLI.
- tests/test_safety.py: временные синтетические фикстуры вне музейного архива.
- config.json: несекретные пути.
- docs/museum-standard.md: полученный официальный стандарт.
- CHECKPOINT_1.md: результаты первого запуска.

Синтетические байты тестов не являются пригодными WAV/видео.
Расширение файла отмечает только кандидата для будущей технической проверки.
Museum ID тестовой фикстуры не выбирает реальную пластинку.
