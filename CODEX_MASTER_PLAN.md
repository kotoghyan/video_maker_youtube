# CODEX_MASTER_PLAN

## Назначение
Разработать систему подготовки контента для YouTube и Instagram на основе локального архива оцифрованных виниловых пластинок музея.

## Согласованные решения

### Шаг 1 — Режим публикации: A (с подтверждением)
- Система автоматически готовит контент, тексты, обложки и метаданные для публикаций.
- Каждая публикация требует явного подтверждения владельца аккаунтов.
- Без подтверждения публикация запрещена; подтверждение одного материала не распространяется на другие материалы или версии.
- После публикации фиксировать платформу, статус, время, ссылку и возможные ошибки в отдельном журнале.

### Шаг 2 — Источник: B (локальная папка)
- Источником служит локальная папка на компьютере пользователя.
- Отслеживать появление новых записей по Museum ID; не запускать обработку до завершения копирования и проверки готовности файлов.
- Читать аудиофайлы, фотографии и JSON-метаданные в существующей музейной структуре.
- Оригиналы доступны только для чтения; никогда не менять исходные файлы, Museum ID, имена архивных файлов, папки и JSON.
- Черновики и временные/экспортные файлы хранить отдельно от музейного архива.
- Не добавлять поля в музейный JSON; параметры соцсетей хранить в отдельном рабочем хранилище.
- Схему музейных данных брать исключительно из официальной документации проекта: https://docs.google.com/document/d/16gsC0nYDbEBKahcXSvAxnK8yBGeGM-qvJP3Ixm6TUSc/edit?tab=t.0

### Шаг 3 — Форматы контента (выбрано 4 из 5)
**Готовить:**
1. YouTube — полные видео, основанные на оцифрованных записях.
2. Instagram Reels — вертикальные ролики.
3. Instagram — посты и карусели.
4. Instagram Stories — анонсы и короткие истории.

**Не включать по умолчанию:** YouTube Shorts.

- Для каждого формата формировать отдельный черновик для согласования.
- Проверять наличие необходимых прав на музыку, изображения и сопутствующие материалы; неопределённость отправлять на ручную проверку, а не считать разрешением.
- Реализовывать публикацию только посредством разрешённых официальных API и доступных функций аккаунтов; для неподдерживаемых форматов предусмотреть подготовку к ручной публикации.

### Шаг 4 — Языки публикаций: B (армянский + английский)
- Создавать названия, описания, подписи, текстовые элементы и релевантные хештеги на армянском и английском языках.
- Сохранять оригинальные названия произведений, имена исполнителей и иные исторические данные без искажения; переводы и транслитерации не должны подменять оригиналы.
- Не добавлять русский как обязательный язык публикации.
- Языковые версии размещать в черновиках для утверждения; не публиковать автоматически.
- Источником фактических сведений служат проверенные музейные метаданные; неизвестные сведения не выдумывать.

### Шаг 5 — Выбор пластинки: B (по Museum ID)
- Пользователь вручную вводит Museum ID пластинки для подготовки контента.
- Система ищет точное соответствие Museum ID в указанном локальном архиве и проверяет полноту материалов.
- После выбора ID готовить черновики четырёх согласованных форматов: полное YouTube-видео, Instagram Reels, пост/карусель и Stories.
- Не запускать создание контента для других Museum ID по собственной инициативе; не выбирать пластинку автоматически.
- При отсутствии файлов, неоднозначном соответствии или недостатке метаданных выдавать сообщение об ошибке/запросить уточнение; не подменять запись другой.
- Отслеживать уже подготовленные и опубликованные материалы для конкретного ID, чтобы избежать случайных дубликатов; повторная подготовка только по команде пользователя.
- Каждая публикация независимо требует явного утверждения (шаг 1).

- Использовать путь как конфигурируемый параметр `ARCHIVE_ROOT`, а не жёстко вшивать в код.
- Архив открывать только для чтения; не записывать в него черновики, логи, кэш, рендеры или токены.
- Перед обработкой выбранного Museum ID проверять доступность пути и наличие нужных файлов; если OneDrive хранит некоторые файлы только в облаке, сообщать об этом, а не считать их доступными локально.
- Выходные файлы располагаются отдельно от архива (см. шаг 7).

### Шаг 7 — Рабочая папка: A (отдельно от музея)
- Корневая рабочая папка: `C:\Users\gjano\OneDrive\Desktop\Vinyl_Social_Media`.

- Здесь хранить временные материалы, результаты рендеринга, черновики текстов, обложки, записи согласований и журнал публикаций.
- Разделять результаты по Museum ID; запрещено изменять или перезаписывать оригиналы в `ARCHIVE_ROOT`.
- Не хранить API-ключи и токены в синхронизируемой папке OneDrive; использовать безопасное системное хранилище секретов.
- Перед созданием файлов проверять доступность пути, свободное место и наличие неоконченных OneDrive-синхронизаций.

## Обязательное правило — выбор медиа по папкам и описание произведений
- После ручного выбора Museum ID найти папку именно этой пластинки внутри `ARCHIVE_ROOT` и проверить наличие подпапок `VIDEO`, `IMAGES`, `TRACKS` и музейного JSON-файла. Не считать наличие папки доказательством наличия пригодных файлов: проверить её содержимое.
- **Если в `VIDEO` есть пригодные видеофайлы:** использовать соответствующее видео как основной видеоматериал для подготовки публикации (YouTube и, при технической пригодности, Instagram Reels/Stories); дополнительно использовать доступные фотографии из `IMAGES`, аудио из `TRACKS` и сведения из JSON для оформления согласованных форматов. Не подменять исходный звук без явного решения пользователя.
- **Если папки `VIDEO` нет или в ней нет пригодного видео:** создавать видеоряд для требующих видео форматов **только** из фотографий папки `IMAGES`, а звуковую дорожку брать **только** из `TRACKS`. Для каруселей/постов использовать изображения `IMAGES`; сопровождать тексты информацией из JSON. Не загружать сторонние картинки, стоковые видео и сторонние аудиозаписи вместо архивных материалов.
- **Каждое отдельное произведение/трек** должно иметь собственные корректные название, авторство, исполнителей и прочие доступные фактические сведения, извлечённые из музейного JSON в соответствии с его действующей схемой. При нескольких произведениях на одной пластинке нельзя использовать общее описание как замену данным о каждом произведении.
- Сопоставлять файлы из `TRACKS` и `VIDEO` с произведениями по имеющимся идентификаторам, именам файлов и связям в JSON; не угадывать соответствие по порядку файлов, когда оно не подтверждается метаданными.
- Если одна сторона пластинки представляет собой одно цельное произведение (например, аудиоспектакль), сохранять такую группировку, как задано архивным JSON, без искусственного дробления.
- Для двуязычных описаний использовать армянский и английский (шаг 4). Факты брать из JSON, сохранять оригинальные имена и названия; отсутствующие данные не выдумывать.
- Если нет JSON или невозможно надёжно связать произведение с медиа, остановить подготовку соответствующего материала и сообщить, чего не хватает. Если `IMAGES` или `TRACKS` отсутствуют и нет пригодного варианта из `VIDEO`, отмечать невозможные форматы как требующие решения пользователя, а не создавать фиктивный контент.
- Все исходные файлы использовать только для чтения. Созданные ролики, копии, описания и предпросмотры сохранять в `WORK_ROOT` по Museum ID; каждую публикацию по-прежнему отправлять на отдельное подтверждение.

### Шаг 8 — Визуальный стиль: A (музейный)
- Оформлять YouTube-видео и материалы Instagram в сдержанном музейном стиле: реальные фотографии пластинки, конверта и этикеток из `IMAGES`, читаемые архивные подписи, минимум анимации.
- При наличии пригодного материала в `VIDEO` использовать его как основу видео согласно правилу выбора медиа; не заменять его декоративной анимацией.
- Если `VIDEO` отсутствует, создавать спокойный видеоряд из `IMAGES` со звуком из `TRACKS`, без сторонних изображений и аудио.
- Не добавлять Museum ID в публикуемые заголовки, описания, подписи, хештеги, видео, обложки и Stories. Указывать название конкретного произведения и подтверждённые сведения об авторах/исполнителях из JSON. Для текстов использовать армянский и английский; не выдумывать исторические факты.
- Не применять агрессивные переходы, визуализаторы звуковых волн, произвольные эффекты и не имитировать исторические кадры.
- Форматы и соотношения сторон адаптировать для каждой площадки без обрезания важных надписей на архивных фото.
- Перед публикацией предоставлять на утверждение предпросмотр видеоряда, звука и двуязычных подписей.

### Шаг 9 — Единица публикации: D (выбор для каждой пластинки)
- После ввода Museum ID считать JSON и вывести список произведений и сторон в музейной группировке, включая цельные произведения на стороне (например, аудиоспектакль).
- До подготовки финальных роликов спросить, что делать с выбранной пластинкой: **(1) всю пластинку**, **(2) выбранные произведения по отдельности** или **(3) оба варианта**.
- При выборе отдельных произведений дать пользователю указать конкретные произведения/стороны; не дробить цельное произведение искусственно.
- Для каждого выбранного материала проверить соответствие файлов в `VIDEO` / `TRACKS` / `IMAGES` и JSON; не предполагать соответствия без подтверждения.
- Если выбран вариант «вся пластинка», включить все произведения в правильной последовательности и описать каждое по музейному JSON; если отдельные произведения — составить отдельные описания для каждого.
- Сохранять выбор пользователя для данного Museum ID в рабочей папке `WORK_ROOT`, **не** дописывая новые поля в музейный JSON.
- По-прежнему готовить только согласованные форматы площадок (шаг 3), а каждый готовый материал отдельно направлять на подтверждение до публикации (шаг 1).

- Не публиковать материалы, пока владелец явно не подтвердил конкретную публикацию и не выбрал действие отправки или планирования. Утверждение черновика само по себе не запускает отправку.

- Если платформа предоставляет собственный подтверждённый механизм отложенной публикации через API, его использование можно реализовать отдельно с прозрачным отображением статуса и отмены; не предполагать наличие такой функции для всех типов контента.
- Вести журнал: Museum ID, произведение, формат, целевая платформа, запланированное и фактическое время, идентификатор/ссылка при успехе, ошибки и повторы.

Проверять применимость конкретного сценария входа и разрешений; для публикации Stories могут действовать дополнительные ограничения по типу аккаунта.

### Шаг 36 — Сбои публикации: B (безопасный автоматический повтор)

Записи атомарно сохранять в отдельном JSON-журнале в `WORK_ROOT`, не в музейных JSON; не сохранять в журнале токены и другие секреты.

### Шаг 37 — Хранение результатов после публикации: B (сохранять готовое, удалять временное)

Оригиналы в `ARCHIVE_ROOT` остаются неизменными.

Не удалять утверждённые экспортные версии, используемые исходные копии, если они нужны для воспроизводимости, или журналы.
- Перед очисткой сверять статус каждой публикации и наличие сохранённых финальных материалов; не удалять временные данные для заданий `draft`, `scheduled`, `uploading`, `failed`, `needs_review` или с неопределённым результатом, если они могут потребоваться для повторной попытки.

Сначала показывать/записывать перечень удаляемых файлов, затем удалять по утверждённым правилам и регистрировать результат в рабочем журнале.
- Если материал опубликован лишь на одной из двух платформ, не удалять промежуточные файлы, необходимые для оставшихся запланированных/неудавшихся публикаций. Ошибка очистки не отменяет успешную публикацию: отмечать её отдельно.
